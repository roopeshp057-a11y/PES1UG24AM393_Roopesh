# Static Code Analysis — Issues Report

| Issue | Type | Line(s) | Description | Fix Approach |
|---|---|---|---|---|
| Shell Command Execution (`B605`) | Security (High) | 56 | `os.system("lp badges_" + eventName + ".txt")` spawns a process with a shell, exposing the application to shell command injection (CWE-78). | Replaced with `subprocess.run(["/usr/bin/lp", f"badges_{event_name}.txt"], check=False)` using an argument vector without shell execution. |
| Insecure Deserialization (`B301`, `B403`) | Security (Medium) | 2, 51 | `pickle.load()` deserializes arbitrary Python objects from untrusted files, potentially executing malicious bytecode (CWE-502). | Replaced `pickle` with `json` (`json.dump` and `json.load`) using safe UTF-8 text file storage (`events.json`). |
| Pseudo-Random Number Generator (`B311`) | Security (Low) | 3, 72 | `random.choice()` uses Mersenne Twister which is predictable and flagged for security-sensitive randomness (CWE-330). | Replaced `random.choice()` with `secrets.choice()` from Python's cryptographically secure `secrets` library. |
| Mutable Default Argument (`W0102`) | Bug | 9 | `guests=[]` in `createEvent` is evaluated once at function definition time. All events created without explicit `guests` share the same list in memory, causing guest cross-contamination. | Changed default parameter to `guests=None` and initialized `guests = [] if guests is None else list(guests)` inside the function body. |
| Unused Function Parameter (`W0613`) | Code Quality | 39 | `sortOrder` parameter in `guestReport` was accepted in signature but completely ignored by sorting logic. | Implemented sorting logic that respects `sort_order` parameter (`"desc"` for descending, default ascending) and provided default argument. |
| Unnecessary `else` After `return` (`R1705`) | Refactoring / Style | 33-36 | `eventStatus` used `else` block immediately following a `return` statement in the `if` branch. | Removed the `else` keyword and de-indented the fallback return statement directly into the function body. |
| Non-Standard Naming Conventions (`C0103`) | Code Quality | 9, 15, 27, 32, 39, 44, 49, 54, 66 | Function and parameter names used camelCase (e.g., `createEvent`, `eventName`, `registerGuest`, `seatsLeft`, etc.) violating PEP 8 `snake_case`. | Renamed all functions and parameters to `snake_case` (e.g., `create_event`, `event_name`, `register_guest`, `seats_left`, `remaining_seats`). |
| Missing Documentation (`C0114`, `C0116`) | Code Quality | 1, 9, 15, 27, 32, 39, 44, 49, 54, 59 | Module and all functions lacked docstrings explaining their purpose, parameters, and return behavior. | Added descriptive PEP 257 docstrings for the module and all functions, keeping line length under 79 characters. |
| Whitespace and PEP 8 Formatting (`E231`, `E225`, `E261`, `E305`) | Style / Formatting | 61, 66, 75, 79 | Formatting errors including missing whitespace after comma (`"Rooftop",2`), missing whitespace around operator (`left=seatsLeft`), insufficient spaces before inline comments, and single blank line before `main()`. | Formatted code to adhere to PEP 8 standards: added spaces around operators, after commas, 2 spaces before inline comments, and 2 blank lines after top-level function definitions. |
